# C documentation audit

This directory holds the data for the audit of the Rust documentation against the C library's documentation headers.
The procedure is in `docs/superpowers/plans/2026-10-19-c-docs-audit.md`.

## Files

`c-headers.tsv` is generated by `c-docs headers reference/starlink-ast/src`.
It lists every documentation header in the C sources, with columns `kind name alias file digest`.
`digest` is the FNV-1a 64 hash of the header's C text without its `Authors:`, `Copyright:`, `History:` and `Licence:` sections, so `tools/oracle_fixtures/check_c_headers_fresh.sh` reports a header whose body changed as well as one that was added, removed or renamed.
A changed digest means the matching ledger row must be re-reviewed against the new text.

`ledger.tsv` has one row per header in `c-headers.tsv` and records what became of it.
It is edited by hand as rows are reviewed.
`c-docs init-ledger c-headers.tsv` writes the initial version.

## Ledger columns

The columns are tab separated, after a header line.

- `kind`: `class`, `function` or `attribute`, as in `c-headers.tsv`.
- `name`: the name in the C header.
- `file`: the C source file holding the header.
- `rust_item`: the Rust items that document the header, as `Owner::item` or `Owner`, separated by `;`.
  It is empty when the header has no Rust item.
- `reason`: why there is no Rust item.
  It is empty when `rust_item` is set.
- `reviewed`: `yes` once the row has been audited, otherwise `no`.
- `note`: free-form text.
  For a `merged` row it is the name of the header it was merged into, which must itself have a Rust item.

## Reasons

- `c-api-only`: the header documents a C calling convention with no Rust counterpart.
- `not-ported`: the class or function is not part of the port.
- `merged`: the header is documented together with another header's Rust item.

## Gates

`crates/ast-core/tests/test_c_docs_audit.rs` checks that every header has exactly one row, that reviewed rows are well formed, and that the count of unreviewed rows never rises.
