# Upstream sync to `4029b011` (Moc validation and the Plot3D oracle) — design

Pin move `fe26cc9b` → `4029b011`: 35 commits, Starlink/ast PRs #107 (Validate MOC handling against CDS reference library) and #112 (Add testing for Plot3D), 2026-11-21 to 2026-11-27.

## Intent

Upstream checked the Moc class against the CDS HEALPix library and fixed what it found: positions on the cut lines of the HEALPix projections, Mocs with a MaxOrder of zero, Regions covering more than half the sky, the separator of a string MOC, and the memory an initial grid takes.
It then wrote the C oracle the Plot3D port was waiting for, a logging 3D graphics backend with fixture-driven Plot3D tests, and fixed the Plot, Plot3D and CmpFrame defects those tests exposed.

This sync moves the pin past both, so that:

1. the port matches the fixed C wherever it follows C, in particular the XphMap and Moc results the new oracle rows record;
2. the mirrored fixture tree carries the Plot3D oracle (`fixtures/plot3d/`), ready for the Plot3D port to consume;
3. the Plot and CmpFrame fixes the Plot3D tests exposed are in the 2-D Plot before Plot3D is built on it.

The Plot3D port itself is not part of this sync.
It follows, on the design in `2026-11-22-plot3d-design.md` (branch `u/timj/plot3d-design`, to be rebased and revised for the oracle that now exists).

## Decisions already made

- **Sync first, then Plot3D** (the user chose this over moving the pin inside a Plot3D stage and deferring PR #107).
  A submodule pin cannot skip PR #107, and `PLAN.md` §8 already says its fixes are ported in the range that moves the pin past it.
- **Staged, one PR per area**, as the `fe26cc9b` sync was.
  Three stages (below); Claude's call on the split, approved by the user with the additions recorded in "Rules settled".
- **A fresh branch from `main`** for stage 0 (`u/timj/sync-c-xphmap`); the local `u/timj/plot3d` branch is ignored (the user).
- **The port's Moc is validated against the CDS HEALPix library directly** (the user), not only through the values upstream copied into `testmoccds.c`: the reference is a Rust crate, so a Rust test computes the reference at test time and compares.
- **The sync protocol of `CLAUDE.md` applies in full**: quirks the port mirrors and upstream fixed are inverted, stale corpora are regenerated in the range that ports the C behind them, `check_probes_fresh.sh` is run at both pins, and `check_c_headers_fresh.sh` after the move.

## Goals

1. Every behavioral fix in the range is ported, or recorded as not applicable with the reason.
2. Every quirk the port mirrors and upstream fixed is inverted and its `c-library-quirks.md` entry marked `RESOLVED (upstream <hash>)`.
3. Each new or extended C test (`testmoccds.c`, `testplotattr.c`, and the new checks in `testmoc.c`, `testxphmap.c`, `testregions.c`, `testcmpframe.c`, `testmocchan.c`) has a Rust counterpart, or a `PLAN.md` tracker row naming what blocks it.
   `testgrf3dlog.c` and `testplot3dlog.c` get rows saying they land with Plot3D.
4. The fixture tree matches upstream at `4029b011`, including `fixtures/plot3d/`, and every mirrored fixture a Rust harness reads passes: `cap_xphmap_03` in the simplify corpus and the changed rows of `oracle/simplify_fixtures.oracle`.
5. Every probe whose output the pin move changes is regenerated by the stage that ports the C behind it, and `check_probes_fresh.sh` is clean when the last stage merges.
6. A cross-library validation test: the port's Moc agrees with the CDS HEALPix library (`cdshealpix` 0.10.2, the crate behind cds-moc and MOCPy) on the cell holding a position, the cells of a Circle and the cells of a Polygon, computed by the crate at test time over at least the cases `testmoccds.c` covers.
7. Each stage leaves `cargo test -p starlink-ast`, `cargo clippy --workspace -- -D warnings`, `cargo fmt --check`, the docs gates and `tools/fixtures/check_mirror.sh` green.

  The fixture tree is mirrored here; nothing reads it until the Plot3D stages.

  The two tick-value fixes in `plot.c` are ported here only where the port already has the code path (a Plot read from a dump carrying tick values).

  The file is not on this host, and the user has deferred the Java resync as lower-priority work; a `PLAN.md` row names the commits of this range for that resync to re-read when it happens.
- A WebAssembly or C-ABI change.

## Anti-goals

- A heuristic in the XphMap or Moc port that C does not have.
  The margins (`AST__HPXTOL`, 1E-10 radians at the end of a sky line) and bounds (`MAXBOX` 262144, `BOXCHUNK` 65536) are C's named constants, ported with C's names in `//` comments; nothing is tuned to pass a fixture.
- Collapsing C's new `CmpFrame::Equal` into `Frame`'s conversion-based equality with a special case.
  C made it a vtab override; the port's `Frame::equal` seam already exists on `CmpFrame`, and the override goes there.
- A regenerated probe or corpus committed without its C behavior ported.
  A reference that changed only because C changed is regenerated in the commit range that ports that change, never earlier.
- A skip mode anywhere.
  A mirrored fixture that cannot pass yet goes in a named exclusion list with a reason and a companion test that fails when it starts passing.

## Approaches considered

1. **Three stages, one PR per area (chosen, Claude's call).**
   Stage 0 moves the pin and ports XphMap, which the mirrored fixtures need; stage 1 ports Moc and the sky-line fix; stage 2 ports the Plot and CmpFrame fixes.
   Each PR is reviewable and leaves `main` green.
2. **One sync PR.**
   The range is a fifth the size of the `fe26cc9b` sync, so one PR is defensible; rejected because the XphMap rewrite and the Moc port are each a substantial review on their own, and the Plot and CmpFrame fixes are a different reviewer's area.
3. **Pin move alone first, with exclusions for the XphMap rows.**
   Rejected: the XphMap fixes are what the copied fixtures need, and the `fe26cc9b` sync's rule is that stage 0 ports whatever behavior the copied fixtures need for tier 1 to pass.

## Per-stage method

Each stage's plan opens with a triage table built by reading every assigned commit's diff and the Rust site it corresponds to, one row per commit, with one of three verdicts:

- **mirror** — the port reproduces the old C behavior; invert it.
- **missing** — the port never had the old or the new behavior; port the new.
- **n/a** — no observable behavior in the port (C memory handling, documentation, build files, Plot3D-only code), with the reason.

The stage then ports the C, ports or extends the C tests, regenerates the probes `check_probes_fresh.sh` reports as changed by that C, retires the quirks entries, and records the stage in `PLAN.md` §8 with the triage's conclusions, as the `fe26cc9b` stages did.

## Rules settled

- **Stage order and green main.**
  Stages merge in order, each branched from `main` after the previous one merges.
  A probe a later stage owns is left stale and listed in `PLAN.md` §8 until that stage regenerates it; a mirrored fixture that fails for a later stage's reason goes in a named exclusion list with its reason and a companion test, which the owning stage removes.
  None is expected: stage 0 ports what the copied fixtures need.
- **Floating-point results in the new tests.**
  The project's existing rules apply.
  `testmoccds.c`'s tables leave out any cell center within 1E-6 degrees of a Region's edge, so none of its expectations depends on rounding; the port carries that note with the tables.
  Upstream's Plot3D dumps were checked against an FMA build before commit; the port mirrors them unread, so that check is Plot3D's.
- **What "ported" means for the Moc grid bound.**
  `78d4c87a` is a performance change with an observable effect, so it is ported as behavior: the same starting order, the same chunking, the same cells.
  The port's own memory and time are measured once on the Circle of radius 80 degrees at orders 14 to 18 that the commit message quotes, and recorded in the stage notes.
- **The cost of the ported Moc checks** (decided by the user).
  The new `testmoc.c` checks go into tier 1 as C has them.
  C runs them in seconds, so a check that is slow in the port means the port's algorithm differs from C's, and the answer is to port C's algorithm (`PutBox`'s chunking and the `MAXBOX` bound are that algorithm), not to shrink the case.
  Only a check whose cost is inherent once the algorithm matches C's, and still passes about 30 s in the dev profile, is marked `#[ignore]` with the measured cost in its reason and run by hand in release, as `test_huge.rs` mirrors C's `TEST_HUGE` gate; each such case is counted in `PLAN.md` §6.
  None is expected.
- **One equality for Regions** (decided by the user).
  C has one `astEqual`, and region.c's override is what a CmpFrame, a FrameSet or a Plot reaches when a component or Frame slot holds a Region.
  The port's Region `Frame::equal`, which compared only the current Frame, is a pre-existing divergence with no recorded reason; stage 2 makes it delegate to `region_equal`, so Rust has one seam too.
  If the fallout in tests grows past what stage 2 can review, the Region change splits into its own PR that merges before stage 2.
- **Where the Plot3D oracle's fixtures sit.**
  In the mirrored tree, unread, with a `PLAN.md` row.
  The Plot3D stages consume them from there; nothing is copied elsewhere.
- **The CDS library is the reference for Moc, beside C** (decided by the user).
  C is the oracle for how the port behaves; the CDS library is the check that both behave correctly.
  A disagreement between the port and the CDS crate that C shares is a C defect, recorded in `c-library-quirks.md` with a probe and raised upstream, not patched in the port; one that C does not share is a port defect.
- **The Java port resync is deferred** (decided by the user), at lower priority than this sync and Plot3D.
