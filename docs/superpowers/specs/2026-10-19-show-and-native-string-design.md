# `show`, `to_native_string` and typed reads: design

**Status:** approved in conversation 2026-10-19; this document records it.
**Scope:** the Rust counterparts of C's `astShow`, `astToString` and `astFromString`, and a typed way to take a known class out of an `AnyObject`.

## Context

This is the first of three pieces of documentation work, done in this order:

1. This change, so that the documentation has a real Rust item for each of the three C functions.
2. An audit of the C source's documentation headers (68 class, 283 function and 227 attribute descriptions), moving their content into the Rust item docs, with a test-checked ledger mapping every header to a Rust item or a reason.
3. A user guide adapted from SUN/211 (the C edition of `sun_master.tex`) as `ast_core::guide`, rustdoc modules whose examples run as doctests.

Each gets its own spec.

## What C does

All three are in `object.c` and apply to every Object.

- **`astShow`** writes the Object through a Channel created with no attributes set, to standard output (`object.c` `Show`).
  The output is the Native dump with the Channel defaults: comments on, `Full` 0, the default indentation.
- **`astToString`** writes the Object through a Channel created with `"Comment=0,Full=-1,Indent=0"`, to a sink that appends each line and a `\n` to a growing buffer (`astToString_`, `ToStringSink`).
  It is documented as "a minimal textual serialisation" that `astFromString` can read back.
- **`astFromString`** reads one Object from such a string through a Channel and returns it as an `AstObject *` (`astFromString_`); the caller does not know the class in advance.

C's class checks report a pointer of the wrong class with `AST__OBJIN`, "Pointer to <class> required, but pointer to <class> given." (`object.h.in`, `astMAKE_CHECK`).

## Design

### Methods on every class

Every class that is an `AnyObject` variant, and `AnyObject` itself, gains:

```rust
/// Writes this object's Native description to standard output, as C's
/// astShow does.
pub fn show(&self) -> AstResult<()>;

/// This object's minimal Native serialisation, as C's astToString returns
/// it: no comments, no default values, no indentation, one item per line,
/// each line ending in '\n'.
pub fn to_native_string(&self) -> AstResult<String>;
```

- Both borrow `self`; neither copies the object into an `AnyObject`.
- Both are generated by one macro over the `AnyObject` variant list, so a class added to `AnyObject` gets them without further work and none can be missed.
- `show` builds its text through a `NativeChannel` with the default `ChannelConfig`; `to_native_string` sets `Comment` false, `Full` −1 and `Indent` 0 on the config, as C does.
- No `#[doc(alias)]` is added for the C names.
- `Display` is not implemented: the Native dump is one of several serializations rather than an object's canonical text, and named methods are the Rust convention for formats.
  `Debug` is unchanged and keeps printing the Rust structure.

### The free function `to_native_string` is removed

`ast_core::to_native_string(&AnyObject)` writes the `show`-style text under the `astToString` name.
It is removed rather than changed, and its callers move to the method:

- Callers that want the compact form call `.to_native_string()`.
- Callers that compare against a commented fixture (the default-Channel dump) build a `NativeChannel` with a string sink, which is what the free function did; a shared helper in `tests/common` keeps those call sites short.

About 100 test files and 2 examples call it, so this is a large mechanical change in its own commit.

### Reading back

`ast_core::from_native_string(&str) -> AstResult<AnyObject>` and `from_native_string_with(&str, &IntraRegistry)` stay free functions.
The class is not known until the text is read, which is the same situation as `Channel::read`, and `AnyObject` is how the port already represents that.
They read either form: the compact text from `to_native_string` and the commented text from `show`.

### `TryFrom<AnyObject>` for every class

Each concrete class implements `TryFrom<AnyObject>`, generated by the same macro:

```rust
let map = PermMap::try_from(from_native_string(&text)?)?;
```

A different class gives `AstError` with `ErrorCode::Objin` (C's `AST__OBJIN`) and the message "Pointer to PermMap required, but pointer to ZoomMap given.", C's wording.
On failure the `AnyObject` is lost, as the error owns no object; a caller that needs to try several classes matches on the enum instead.
This applies equally to the result of `Channel::read`.

## Tests

The tests check the mechanism, not every class's serialization, which the existing round-trip and simplify corpora already cover.

- **`show` and `to_native_string` byte for byte against C, for four cases** that each exercise one part of the mechanism: a ZoomMap with `ID` and `Ident` set (set attributes survive `Full=-1`), a FrameSet (nesting, so indentation and comments), a Box (a Rust type whose AST class name differs) and a KeyMap (an `AnyObject` variant that is boxed).
  A probe under `tools/oracle_fixtures/` runs `astShow` (with standard output redirected to a file) and `astToString` on each, and the expected text is committed.
  The Rust tests compare exactly, with no normalization.
  `show` is checked through the same internal string builder it prints, so the test needs no captured standard output.
- **Read back:** each case's `to_native_string` text reads back and writes the same text again.
- **A concrete class and its `AnyObject` write the same text.**
- **`TryFrom`:** the right class succeeds, a boxed variant comes back unboxed, and a wrong class gives `Objin` with C's message.

## Documentation

- Each method's rustdoc names the C function it corresponds to and the Channel settings it uses.
- The main design spec (`2026-04-20-rust-port-design.md`) gets a revision entry recording the three methods, the removal of the free function, and `TryFrom<AnyObject>`.
- `CLAUDE.md`'s "AST documentation" pointer is corrected: SUN/210 is the Fortran edition of the AST guide and SUN/211 the C edition; both contain the full guide and reference, generated from `sun_master.tex` by `builddocs`.

## Out of scope

- Writing an object to a `Channel` without wrapping it in `AnyObject`; `Channel::write` keeps taking `&AnyObject`.
- `#[doc(alias)]` for C names, which the documentation audit decides for the whole API.
