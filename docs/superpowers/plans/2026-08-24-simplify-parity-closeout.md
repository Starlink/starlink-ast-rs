# Simplify Parity Closeout Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the thirteen named divergences between the port's simplifier and C's, so every reduction C performs is performed here, every reduction C declines is declined here, and no constant without an analogue in the C source decides either.

**Architecture:** The seam structure is already C's after `84cd3ba..25a5094`: `<dyn Mapping>::simplify` is `astSimplify_`, `Mapping::simplified` is the `Simplify` vtab slot with one possible caller enforced by a capability token, and `Mapping::map_merge` is `MapMerge`. What remains is arithmetic inside those seams — two substitutes for C's identity test, a depth cap and a structural hash where C compares with `astEqual`, a swap hung off the wrong nominee, three unported per-class bodies, two unported guards, one missing gate, one dead rewrite, and a convention applied nowhere.

**Tech Stack:** Rust 2024 (`ast-core`), C99 (`reference/starlink-ast` at pin `07fbe2dc`, built with cmake), the `tracing` feature for the port-side simplify trace, `tools/oracle_fixtures/build_simplify_trace.sh` for C's.

**Spec:** [`docs/superpowers/specs/2026-08-24-simplify-parity-closeout-design.md`](../specs/2026-08-24-simplify-parity-closeout-design.md)

## Ordering, and why

Waves are ordered by whether a gate can exist, not by size.

| Wave | Tasks | Why here |
|---|---|---|
| 1 | 1 (A6), 2 (B5), 3 (A1) | Measurable against today's corpus with no new fixture and no new surface |
| 2 | 4 (A2), 5 (A4), 6 (B1), 7 (B2) | Need a new oracle fixture, generated by today's generator |
| 2′ | 8 (A7) | Adds the "nothing changed" vocabulary that Tasks 9 to 12 speak |
| 3 | 9 (A3), 10 (A5), 11 (B3) | Need new expressive surface — a flag pair, an attribute — before a gate can exist at all |
| 4 | 12 (B4) | Needs a Frame-level simplify seam, which is a public-API question |
| last | 13 (C1), 14 | A convention applied in one place is worse than in none; then close the record |

Task 8 sits between the waves deliberately. Task 3 needs a changed-flag out of `simplify_mapping`, which is internal; Task 8 generalises that into the per-class seam's return type, and Tasks 9, 11 and 12 all need it. Doing 8 before 3 would mean rewriting Task 3's mechanism twice.

        &self,
        ctx: &mut super::simplify::MergeCtx,
        where_: usize,
        series: bool,

## Self-review

**Spec coverage.** The spec's thirteen items map onto fourteen tasks: A6→1, B5→2, A1→3, A2→4, A4→5, B1→6, B2→7, A7→8, A3→9, A5→10, B3→11, B4→12, C1→13, with Task 14 carrying the record work that belongs to no single item. §10.17 became one task rather than two even though it contains two changes (the seam and the branch), because the branch is unreachable without the seam and a commit adding only the seam has nothing that exercises it.

**Where I departed from the spec.** Task 9 has three changes where the spec named two — C's `base_simplify` gate at `mapping.c:16853-16855` is a third restricted-mode step the port lacks, found while reading for this plan and not in the spec's inventory. Task 11 adds `SimpVertices` as an attribute, which the spec described as a prerequisite rather than as work; it is in the task because the bend check cannot be tested without it. Both are additions to the spec's scope, not substitutions, and the spec should gain a note in Task 14 if it is to stay accurate.

**Risks, in the order I expect them to bite.** Task 8 changes a trait method's signature at twelve sites and is wave 2′ — early, deliberately, because Task 3 needs a changed-flag and every later task inherits the `Option` convention; if it slips, Tasks 9 and 12 need their `Ok(None)` returns rewritten. Task 10 adds a serialised card to 26 classes, which is the single largest corpus surface in the plan; the round-trip test is the check and it is listed. Task 4 replaces a depth cap with an `equal`-based cycle stack, so a class with a wrong `equal` turns a silent decline into a stack overflow — stated in the task, with the fix being the `equal`, not the cap.

**Fixtures that may not discriminate.** Three tasks depend on generating a fixture that reaches a branch, and §10.17's retired `normmap_frame_simplifies` is the precedent for getting that wrong invisibly. Tasks 9, 11 and 12 therefore each check the generated pair *before* any Rust is written, with a named expected diff and a stated response if it does not appear. Task 9's is the weakest: if C does not dump the `AlSimp` card at all, the fixture cannot show the clear and the task falls back to a unit test — I have written the fallback into the step rather than assuming the strong case.

**Placeholder scan.** No `TODO`, no `XXX`, no unnamed constant. Two values are deliberately undetermined at plan time: the uncertainty magnitude Task 11's bend check needs (found by generating, with the step saying to record what discriminated) and whether Task 9's `AlSimp` card exists. Both are questions only the pinned C can answer, and both have a written procedure rather than a guess.

**Type consistency.** `Option<DynMapping>` (Task 8), `Option<DynFrame>` (Task 12) and `(DynMapping, bool)` (Task 3) all encode the same thing — C's "is this the object I passed in?" — in three shapes. That is deliberate: Task 3's flag exists because `simplify_mapping` already computes it internally, and the two `Option`s are C's own convention of returning a clone to mean "no change". They must not multiply further; Task 12 says explicitly to derive its `None` from Task 8's reporting function rather than a fresh `equal`.

**The one thing I could not close.** §9.2 keeps a row open. Five of C's clear-on-set attributes have no setter in the port, and I chose not to add public setters to give a convention somewhere to live — that would be an attribute-surface change the spec did not ask for. The consequence is that when those setters do land, nothing fails if the author forgets the rule. A test that enumerated every setter and asserted it clears would close it, and I do not know how to write that in Rust without a macro over the whole attribute surface, which is a larger change than the gap it guards.
