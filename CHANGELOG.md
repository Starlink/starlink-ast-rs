# Changelog

All notable changes to the published crates of this repository, `starlink-ast` and, once it is published, `starlink-ast-capi`, are recorded here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).
The crates follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as Cargo applies it: while a version is `0.y.z`, a change that breaks the public API raises `y` and anything else raises `z`.
Each crate is versioned on its own, so a version heading names its crate, and an entry under `Unreleased` names its crate when the repository publishes more than one.

## [Unreleased]

### Added

- `starlink-ast`: `constants::MAX_NATIVE_NESTING` (130), `MAX_EXPRESSION_NESTING` (100) and `MAX_UNIT_NESTING` (100): a Native dump that nests Objects deeper fails to read with `ErrorCode::Lderr`, a MathMap expression nested deeper fails with `ErrorCode::Miopa`, and a units string nested deeper fails with `ErrorCode::Badun`, where the C library overflows its stack for the first and last and compiles the second. Input nested to each limit reads on a 2 MiB stack in an unoptimized build.
- `starlink-ast`: `constants::MXAXES`, 65536, the most inputs or outputs a Mapping, or axes a Frame, may have, as in the C library. A constructor given more, or a dump describing more, fails with `ErrorCode::Badni`, `ErrorCode::Badno` or `ErrorCode::Naxin` and the C library's messages; `BasicFrameBuilder::build`, `ZoomMap::new`, `WinMap::new`, `PermMap::new`, `UnitNormMap::new` and `CmpMap::new` check it.
- `starlink-ast`: `simplify` checks, as the C library now does, that the Mappings it merges in series feed one another (`ErrorCode::Innco` otherwise) and that each merge leaves them with the numbers of inputs and outputs they had (`ErrorCode::Inter` otherwise, an internal error). Neither is expected from a Mapping the library builds.
- `starlink-ast`: `GrfCap::Unicode`, which a backend that draws any Unicode character reports, and `Frame::minus_signs`, which finds the minus signs in a formatted axis value, leaving out the hyphens of a date, an escape sequence or the Format's own text. A Plot drawing through such a backend draws the minus sign of a negative numerical label as U+2212, as long as a digit, rather than a hyphen; `SvgGrf` reports the capability when `SvgOptions::unicode` is set, which it is not by default, so a Plot still draws to it as to the C library's logging backend.
- `starlink-ast`: `SvgOptions::erase_under_text`, which fills each text's box with the background before drawing it, as the C library's PGPLOT and PLplot backends do, and `SvgOptions::equal_aspect`, which draws as PGPLOT does after `PGWNAD(0, 1, 0, 1)`: on the largest square centred inside a margin of four character heights, with characters 1/40 of the image's shorter side, turned the way their up vector points, in Helvetica and measured with its widths. Both are off by default, so `SvgGrf` still draws as the C library's logging backend does.
- `starlink-ast`: units written with the micro sign or Greek mu (`µm`, `μJy`) and with the Ångström sign or A with ring above (`Å`), as scientific plots write them, convert as `um`, `uJy` and `Angstrom` do. The C library, written before Unicode, knows only the ASCII spellings.
- `starlink-ast`: `Plot::grf`, with `set_grf`, `test_grf` and `clear_grf`: the C library's Grf attribute, which the Rust library keeps but does not read, since a backend is passed to each drawing method.
- `starlink-ast`: `Plot::get_attribute_with_grf`, with the `attribute-strings` feature: a get whose grid-dependent values are worked out through a given graphics backend.
- `starlink-ast`: the `attribute-strings` feature, off by default, with the `attributes::Attributes` trait: `set_attributes`, `set_attribute`, `get_attribute`, `test_attribute` and `clear_attributes` set, read, test and clear attributes by name from strings in the C library's syntax (`"Ident=detector, UseDefs=0"`), with the C library's values and error messages. So far it reaches the attributes of a plain Frame (`BasicFrame`) of a `SkyFrame` (`Equinox`, `SkyRef`, `SkyRefIs`, `AsTime(1)` and the rest), of a `SpecFrame` and a `DSBSpecFrame` (`StdOfRest`, `RestFreq` in GHz or with units, `SourceVel`, `DSBCentre`, `SideBand` and the rest), of a `TimeFrame` (`TimeScale`, `TimeOrigin` as a number, with units or as a date, `LTOffset`) of a `CmpFrame`, which hands a name to the Frames its axes belong to (`System(1)=wave`, `RestFreq=230.5`), and of a `FrameSet` (`Base`, `Current` by index or Domain, `Invert`, `Variant`), which hands every other name to its current Frame and keeps its Mappings consistent once per setting string, as the C library does, and of a `Plot` (`Grid`, `Gap(1)`, `Edge(2)=left`, `Colour(Axes)=2` and the rest), whose attributes that depend on the grid it would draw read as the values the grid would use, and of a `FitsChan` (`Encoding`, `Card`, `Warnings`, the read-only `NCard`, `CardName` and the rest, and the Channel attributes `Comment`, `Full` and the rest): those every object has (`ID`, `Ident`, `UseDefs`, `Class`), the Mapping attributes, Frame's own (`Title`, `Epoch`, `System`, `Label(1)`, `Unit(2)` and the rest) and those of an axis's Axis object (`Ident(2)`); other classes fail with an error saying they are not yet supported.
- `starlink-ast`: `Plot::draw_region_outline`, which draws the outline of a Region in a Plot's current Frame, as the C library's `astRegionOutline` does, call for call.
- `starlink-ast`: `Draw::set_clip_region` and `Draw::clear_clip_region`, which clip what a Plot draws to a box in any of its Frames, as the C library's `astClip` does.
- `starlink-ast`: `Draw::draw_gen_curve`, which draws the curve a Mapping from distance to position describes, and `Draw::draw_mark`, which draws markers, as the C library's `astGenCurve` and `astMark` do, call for call.
- `starlink-ast`: `Draw::draw_curve`, which draws the geodesic between two positions in the current Frame, `Draw::draw_poly_curve`, which draws the geodesics joining a list of positions as one line, and `Draw::bounding_box`, the box enclosing what a Plot last drew, each as the C library's `astCurve`, `astPolyCurve` and `astBoundingBox` do, call for call.
- `starlink-ast`: `Plot::used_values`, the values a grid uses for the attributes whose defaults depend on what it draws (`Gap`, `Centre`, `Edge`, `Labelling` and the rest), each the attribute's own value if set, else the grid's choice, as the C library's string getter reports them; the grid's tick spacing and choice of exterior or interior labelling follow the C library's.
- `starlink-ast`: the `plot::Draw` trait, through which a Plot draws on a `Grf` backend, with `draw_grid`, which draws an annotated coordinate grid as the C library's `astGrid` does, call for call, `draw_grid_line`, which draws a curve along one axis of the current Frame as the C library's `astGridLine` does, call for call, `draw_border`, which draws the border of the regions of valid coordinates as `astBorder` does, and `draw_text`, which draws justified, rotated text with the C library's escape sequences (`%^50+` and the rest) as `astText` does. The drawing methods carry a `draw_` prefix where the plain name is an attribute's (`border` and `grid` are the `Border` and `Grid` attributes).
- `starlink-ast`: a Plot whose current Frame is a Region draws its border and grid as the C library does, the border following the edge of the Region, traced along the Region's own boundary where its class can do that.
- `starlink-ast`: a Plot is saved and restored in the Native form as the C library writes and reads it, through any Channel and as `AnyObject::Plot`, with its attributes, clipping region and graphics box.
- `starlink-ast`: Plot's per-element style attributes `Style`, `Font`, `Colour`, `Width` and `Size`, which take a `PlotElement`; setting, testing or reading a group such as `PlotElement::Axes` acts on each of its members, as the C library's `Colour(Axes)` does.
- `starlink-ast`: Plot's own attributes, from `Tol` to `LogPlot`, with the C library's defaults; setting `LogPlot` maps an axis of the plotting area logarithmically, as in C. `Gap`, `Centre` and `Abbrev` are `tick_gap`, `tick_centre` and `abbreviate`, since `Frame` already has `gap`, `centre` and `abbrev`. Until grids are drawn, an unset attribute reads as its fixed default, not as the value a grid would use.
- `starlink-ast`: `Plot`, a FrameSet whose base Frame is a graphics coordinate system, built from a Frame, FrameSet, Region or Plot as the C library's `astPlot` builds it; it transforms and is searched as a FrameSet. Frames are added, removed and selected through the Plot itself.
- `starlink-ast`: `Frame::as_frameset` and `Mapping::as_frameset`, which give the FrameSet a Frame or Mapping is, so that code treating FrameSets specially treats a Plot as the FrameSet it holds.
- `starlink-ast`: the `grf` module: the `Grf` trait, through which a Plot will draw, and `LogGrf`, a backend that logs each drawing call as the C library's logging graphics module does.
- `starlink-ast`: `SvgGrf`, a `Grf` backend that draws to SVG as the C library's logging graphics module does, with `SvgOptions` for the image size.
- `starlink-ast`: `Frame::gap`, `centre`, `abbrev` and `fields`, which choose tick spacing and split and abbreviate formatted axis values for plot annotation, as the C library's do, with `FieldSplit` to hold the fields of a value.

### Changed

- `starlink-ast`: a FitsChan refuses, with `ErrorCode::Bdfts`, a card holding a character that is not printable ASCII, which a FITS header may not hold: one given to `put_fits`, `put_cards`, `from_header` or a source, or a keyword name, string value or comment given to a `set_fits_*` method. A write whose cards would hold such a character, such as a Native write of a Frame with a Unicode Title, fails the same way and leaves the FitsChan as it was. The C library stores any bytes.
- `starlink-ast`: a count read from a dump that would need more than 9999999 values, the most a dump can name, is refused with `ErrorCode::Lderr`, as the C library refuses one for a MatrixMap or PointSet: a LutMap's table length, a PolyMap's coefficients and powers, a SplineMap's coefficients, a KeyMap entry's length, a Table's rows, a Plot's tick marks, a Region's MeshSize and a unit or diagonal MatrixMap's elements. An Object with many items reads in time proportional to their number.
- `starlink-ast`: a unit expression that takes the logarithm or square root of a constant out of range, or divides by zero, gives the C library's message, such as `Illegal negative or zero constant value '-0.872603' encountered.` (`ErrorCode::Badun`), from setting the Unit, from every conversion that uses it, and from a FluxFrame's System; `TimeFrame::time_origin_cur` returns `AstResult`, as the conversion to the current Unit can fail.
- `starlink-ast`: `FrameSet::variant`, `test_variant`, `clear_variant` and `all_variants` return `AstResult`: Frames that mirror each other's variants in a loop, as in a FrameSet read from a corrupt dump, give `ErrorCode::Frsin`, as in the C library, where they looped for ever.
- `starlink-ast`: `UnitMap::new`, `ShiftMap::new` and `CmpFrame::new` return `AstResult`, as the C library refuses more than `constants::MXAXES` coordinates or axes; each was infallible.
- `starlink-ast`: an invalid axis permutation, given to `Frame::perm_axes` or read from a dump, fails with the C library's two messages, `astPermAxes(<class>): Invalid axis permutation array.` and `Each axis index should lie in the range 1 to <n> and should occur only once.`; `frames::validate_permutation`, which gave the port's own text, is removed.
- `starlink-ast`: Frame geometry (`distance`, `angle`, `ax_angle`, `ax_distance`, `ax_offset`, `offset`, `offset2`, `intersect`, `resolve`, `norm` and the line functions) takes an infinite coordinate to be a number, as the C library does, testing only for `BAD_VALUE`. A NaN coordinate is a number there too, as in C, so a result C computes as NaN, from infinities or from a NaN given, is NaN. It took an infinite or NaN coordinate to be bad and gave `BAD_VALUE`.
- `starlink-ast`: a sky axis value whose formatted text would pass 70 characters, about 1e57 degrees or more, is formatted as `<bad>`, as the C library now does; its digits had no meaning.
- `starlink-ast`: two `MathMap`s are equal when their functions compile to the same operations and constants in the directions they are used, as in the C library: names of variables, spacing and constants that differ within the comparison tolerance no longer matter, and an inverted MathMap is compared through the functions it then uses. They were compared by the text of their functions and their `Invert` flags, so a MathMap and an inverted one with matching functions, or two MathMaps that differ only in variable names, did not cancel in `simplify`.
- `starlink-ast`: a `PolyMap` created without forward coefficients has no iterative inverse: `iter_inverse` defaults to false for it, so one with no coefficients at all has no inverse transformation, and `set_iter_inverse(true)`, or a Native dump with `IterInv = 1`, fails with `ErrorCode::Attin`. Its error messages are now the C library's.
- `starlink-ast`: a FITS header with a CDELT of zero now gives that axis a pixel size of a millionth of its CRVAL, or 1.0 if CRVAL is zero or absent, as the C library now does; it was 1.0 whatever CRVAL was.
- `starlink-ast`: a DssMap gives bad values for a sky position 90 degrees or more from its plate centre, and for a position its plate solution cannot evaluate, as the C library now does; the first had been given the pixel position of the point on the opposite side of the sky.
- `starlink-ast`: the minimum supported Rust version is now 1.87, which `nalgebra` 0.34 requires; the 1.85 declared before was not enough to build `starlink-ast` with it.
- `starlink-ast`: `AnyObject` is `#[non_exhaustive]`, so the classes still to be added to it will not each be a breaking change; a `match` on it needs a wildcard arm.
- `starlink-ast`: building no longer needs a C compiler: PAL and ERFA are now Rust, bit for bit the results of the C they replace.
- `starlink-ast`: WcsMap projections give upstream wcslib 8.10's results where the wcslib code AST carries had differed: QSC within 0.008 degrees of face 4's centre, HPX with H and K other than 4 and 3, at the poles, on facet edges and at native longitude +180, ZPN with a degree-2 polynomial on the far side (now bad), PCO near the equator, COP at the poles, and MER near the pole.
- `starlink-ast`: a WcsMap reverse projection that lands a native longitude or latitude just past a limit, by up to wcslib's tolerance for the projection (1e-13 to 1e-11 degrees), returns the limit rather than bad, as wcslib does.
- `starlink-ast`: SlaMap's FK5 to FK4 conversion (`Fk54z`) applies the fictitious FK4 proper motion to the unit vector, as ERFA and SLALIB do, rather than linearly in RA and Dec; away from B1950 this changes points the motion carries close to a pole by up to 28 mas at B1980 and 0.3 arcsec at B2050, and others by about 1e-14 radians.
- `starlink-ast`: the vendored ERFA is version 2.0.1, with the IAU 2012 astronomical unit; spectral and time conversions give the same results as before.
- `starlink-ast`: SphMap computes its arctangents, sines and cosines with branchless kernels that the compiler vectorizes; on large point sets its forward transform runs about three times faster and its inverse about 1.7 times on Apple silicon, and 2.4 and 3.5 times faster on x86-64, where the loops run in a build for AVX2 and FMA when the CPU has them. Each sine, cosine and arctangent may differ from earlier releases by up to 1 ULP, so a Cartesian component, the product of a sine and a cosine, by up to 3 ULP; results do not depend on how many points are transformed together.
- `starlink-ast`: a WcsMap whose projection parameters are unusable reports `ErrorCode::Wcspa` from every transform that has a good point, rather than only from the first, after which it gave bad values; the C library reports it only once.
- `starlink-ast`: every WcsMap projection, and TPN's polynomial, is Rust, and the crate no longer compiles any C for wcslib; results are bit for bit those of the C projections they replace, and WcsMap transforms whole slices through the projection kernels.
- `starlink-ast`: WcsMap's TAN projection uses vectorizable trigonometry in bulk forward transforms (native spherical to projected coordinates), which on large point sets run between two and three times faster; results may differ from earlier releases by a few ULP.
- `starlink-ast`: WcsMap's SIN projection uses vectorizable trigonometry in bulk forward transforms (native spherical to projected coordinates), which on large point sets run about 1.7 times faster through an orthographic WcsMap, the projection itself 2.4 to 3 times for the orthographic form and 1.8 to 2.3 times for the synthesis form; results may differ from earlier releases by a few ULP, or, where the synthesis form's terms cancel, by a few units of 2^-52 of the larger term, and a point is bad exactly when it was.
- `starlink-ast`: WcsMap's ZPN projection uses vectorizable trigonometry for the sine and cosine of the native longitude in bulk forward transforms (native spherical to projected coordinates), which on large point sets run about 1.7 times faster through a WcsMap, the projection itself three times; results may differ from earlier releases by a few ULP, and a point is bad exactly when it was.
- `starlink-ast`: WcsMap's TPN projection uses vectorizable trigonometry for the gnomonic stage of bulk forward transforms (native spherical to projected coordinates), which on large point sets run 10 to 20% faster; results may differ from earlier releases by up to 1e-10 of a coordinate, the square of the tolerance of TPN's Newton iteration, plus the rounding error of TPN's polynomials, and in tests by at most 1e-14 of a coordinate with macOS's libm on Apple silicon and 6e-13 with its x86-64 libm; points whose projection lies on or very near an axis of the projection plane give the same results as before.
- `starlink-ast`: WcsMap's AZP, SZP, STG, ARC, ZEA and AIR projections use vectorizable trigonometry in bulk forward transforms (native spherical to projected coordinates), and SZP's in bulk inverse transforms too; on large point sets the projections themselves run between 1.05 times (SZP with its overlap test) and 3.9 times (STG) faster, and an ARC WcsMap's forward transform about 1.75 times; results may differ from earlier releases by a few ULP, or, where a projection's denominator nearly cancels, by a few units of 2^-52 relative to that denominator, SZP's inverse only in the native longitude, and a point is bad exactly when it was.
- `starlink-ast`: WcsMap's CYP projection uses vectorizable trigonometry in bulk forward transforms (native spherical to projected coordinates), which on large point sets run about 1.9 times faster through a WcsMap, the projection itself 2.2 to 2.4 times; results may differ from earlier releases by a few ULP, or, where the projection's parameter `mu` plus the cosine of the latitude nearly cancels, by a few units of 2^-52 relative to that sum, and a point is bad exactly when it was.
- `starlink-ast`: WcsMap's AIT projection uses vectorizable trigonometry in bulk forward transforms (native spherical to projected coordinates), which on large point sets run about 1.5 times faster through a WcsMap, the projection itself 2.0 to 2.4 times; results may differ from earlier releases by a few ULP, and a point is bad, or an output NaN, exactly when it was.
- `starlink-ast`: WcsMap's COP, COE, COD and COO projections use vectorizable trigonometry in bulk forward transforms (native spherical to projected coordinates), and COO's in bulk inverse transforms too; on large point sets the projections themselves run between 1.1 times (COO's inverse) and 3.2 times (COD) faster, and a COD WcsMap's forward transform about 1.8 times; results may differ from earlier releases by a few ULP, or, where a projection's terms cancel, by a few units of 2^-52 relative to the larger term, COO's inverse only in the native longitude, and a point is bad exactly when it was.
- `starlink-ast`: WcsMap's BON projection uses vectorizable trigonometry in bulk forward and inverse transforms; on large point sets the projection itself runs between 1.2 times (its inverse on a smooth grid) and 2.1 times (its inverse on random points) faster, and a BON WcsMap's forward transform about 1.3 times and its inverse 1.2 times; results may differ from earlier releases by a few ULP, or, where the projection's terms cancel, by a few units of 2^-52 relative to the larger term, its inverse only in the native longitude, and a point is bad exactly when it was.
- `starlink-ast`: WcsMap's TSC and CSC projections use vectorizable trigonometry for the direction cosines of bulk forward transforms (native spherical to projected coordinates), which on large point sets run between 1.2 times (CSC) and 1.9 times (TSC) faster for the projections themselves; CSC's results are unchanged, TSC's may differ from earlier releases by a few ULP, and a point is bad exactly when it was.
- `starlink-ast`: TimeMap applies each conversion step to every point before the next step, as the C library does, rather than every step to one point at a time; on large point sets an MJD to Besselian epoch conversion runs about 1.5 times faster and a TAI to UTC conversion about 1.75 times faster, with bit-identical results.
- `starlink-ast`: SlaMap's FK4 to FK5 and FK5 to FK4 conversions (`Fk45z` and `Fk54z`) are vectorized: they use vectorizable trigonometry for every point of a transform, which on large point sets runs about 1.25 and 1.4 times faster; a single-point transform is slower, by 70% for the forward FK4 to FK5 conversion and 22% for the inverse, though still three to four times faster than the C library; results can differ from earlier releases by up to about 16 units of 2^-53 radian on the sky (more ULP for values near zero) against the previous release's per-value result, and by 1.33e-15 radian against the C library, so downstream pixel coordinates can move slightly (about 3e-10 pixel on a FrameSet from the timj.ast test), and a point is bad exactly when it was.
- `starlink-ast`: SlaMap's FK5 to ICRS and ICRS to FK5 conversions (`Fk5hz` and `Hfk5z`) build their rotation matrices once per transform rather than once per point, so ICRS to FK5 runs about 1.4 times faster on large point sets on Apple silicon; results are bit for bit unchanged.

### Fixed

- `starlink-ast`: a FITS header with a CROTA but without the CDELT of each celestial axis fails to read with `ErrorCode::Bdfts` and the C library's message, where the port read it without the rotation.
- `starlink-ast`: a FITS header with a CAR projection and a huge `NAXIS` is read at once; the CD matrix's rows and columns are counted from the `CD<j>_<i>` keywords present, as in the C library, rather than from `NAXIS`.
- `starlink-ast`: writing a Frame of many axes takes time in proportion to their number, as in the C library, where each axis's values searched the axis permutation; a Frame of 65536 axes was written in seconds. Writing or reading any Object holds about half as much memory as before.
- `starlink-ast`: simplifying a Mapping no longer panics when the merge loop finds a repeating pattern just after a UnitMap in series removed itself from the end of the list; as in the C library, there is then nothing to freeze.
- `starlink-ast`: a line read by a Channel ends at a NUL, as a C string does, so a dump with an item name of NULs reads as one with a blank line. An Object whose End is missing gives first any error its loader gives for what was read, as in the C library, where the error for the missing End came first.
- `starlink-ast`: simplifying a Prism whose component Regions hold bad values no longer recurses until the stack overflows; it stops when the simplification changes nothing, as in the C library.
- `starlink-ast`: a SpecFrame read from a dump with a standard of rest (`SoR`) or alignment standard of rest (`AlSoR`) it does not know fails with `ErrorCode::Attin` and the C library's message, where it was ignored.
- `starlink-ast`: a FITS header whose `NAXIS<i>` value is not a number fails a read with `ErrorCode::Ftcnv` and the C library's messages, as does a write to a FitsChan holding one, where the port took the dimension as unknown.
- `starlink-ast`: a FitsChan write in the Native Encoding that fails removes the cards it had added, as every other write does and as in the C library.
- `starlink-ast`: the Mapping between two Frames of a FrameSet that share a node is the first Frame as a Mapping, as in the C library, where it panicked.
- `starlink-ast`: a Native dump or FITS header holding text that is not ASCII no longer panics when a keyword or a FITS warning would be cut inside a character. A FITS card ends at a NUL, as a C string does, and a FITS keyword name is upper-cased in ASCII only, as the C library's `toupper` does.
- `starlink-ast`: an axis Format with a field width or precision that makes its result longer than 127 characters, such as `%.99999999f`, fails with `ErrorCode::Fmter` before the result is made, as the C library's does, where it allocated the whole result or panicked; a width or precision an `int` cannot hold fails as C's `snprintf` does, and `%g` with a huge precision gives its shortest result. A FitsTable header whose TDIM dimensions multiply past the largest integer gives the error for TDIM and TFORM disagreeing, where it panicked.
- `starlink-ast`: a range in a string MOC is kept as a range, as in the C library, so `27/0-216172782113783807`, the whole sky at the largest order, is read at once; each cell of a range was added in turn. A Moc read from a dump with a negative number of ranges, ranges but no valid MaxOrder, or a negative lower bound fails with C's messages, and its ranges are read in turn rather than sized from their number. A Moc given a longitude far out of range, or infinite, removes whole turns from it first, as in C, where one turn at a time never ended. A Table read from a dump checks that its column and parameter definitions are KeyMaps, taking an empty one for each that is missing, as C does, and that no column name is longer than 100 characters; a FitsTable needs its FitsChan, and a FluxFrame's SpecFrame must be one. A KeyMap's SizeGuess read from a dump no longer sizes its table.
- `starlink-ast`: a Region read from a dump is checked as the C library checks it, with its messages: its points must be a PointSet of at most 9999999 values, and as many as its class has (two for a Circle, Box or Interval, three for an Ellipse, at least one for a Polygon or PointList), its Frame, FrameSet and uncertainty Region must be of their classes, with the uncertainty's axes those of the Region, and a Polygon's vertices must all be defined; the components of a Prism, CmpRegion or Stc must be there, be Regions and have the right axes, and a CmpRegion's operator must be AND, OR or XOR. A System given in a Region's own Frame part is refused, as in C. Such dumps loaded, hung, or panicked when the Region was used. A Prism whose boundary mesh would have more points than a C `int` counts gives `ErrorCode::Inter`.
- `starlink-ast`: a DssMap read from a dump with a plate centre or pixel offsets too large for the DSS FITS keywords' integers fails with the C library's message, and a DssMap no longer absorbs a WinMap that would give it such offsets. An XphMap read from a dump with an Order outside 0 to 27 fails, as in C, and its grid indices are held in doubles, so a position far outside the grid gives a bad value rather than overflowing.
- `starlink-ast`: a SplineMap read from a dump must have two inputs and two outputs, and its spline orders, numbers of coefficients and knots pass the checks `SplineMap::new` makes, before anything is sized from them, with the C library's messages, which `SplineMap::new` now gives too; coefficient counts too large for a C `int` to count are refused. A dump claiming a huge number of coefficients took minutes.
- `starlink-ast`: a WcsMap read from a dump must have as many outputs as inputs, and its longitude and latitude axes are checked as `WcsMap::new` checks them, both with the C library's messages, which `WcsMap::new` now gives too; a negative axis index no longer wraps to a huge one. A WcsMap of unknown projection type, a copy, is not checked, as in C, so one the port refused now loads.
- `starlink-ast`: a PolyMap or ChebyMap read from a dump with a negative maximum power or number of coefficients, or a power outside 0 to its variable's maximum, fails with the C library's message; a LutMap read with fewer than two elements or an increment of zero fails, and one with fewer than two good values has no inverse whatever the dump says, as in C.
- `starlink-ast`: a PermMap, MathMap or MatrixMap read from a dump no longer reads, or allocates for, the number of constants, functions or matrix elements it claims before the data are seen: a PermMap may name at most 99999 constants and refer only to those it has, a MathMap's functions are read in turn and a missing one is an error, as is too few of them, and a full MatrixMap may have at most 9999999 elements, each with the C library's message. Such a dump took minutes, or exhausted memory.
- `starlink-ast`: a Mapping read from a dump is checked as the C library checks it, with its messages: the numbers of inputs and outputs must be those its class allows (a UnitMap's equal, a SphMap's 3 and 2, a SpecMap's 1 or 3 of each, and so on), and the component Mappings, Frame or Regions of a CmpMap, TranMap, RateMap, NormMap, SelectorMap or SwitchMap must be there, be of the right class and fit together. A SpecMap or SlaMap with a missing conversion gives C's `ErrorCode::Badin` message, and a negative number of conversions reads none, as in C.
- `starlink-ast`: a FrameSet read from a dump is checked as the C library checks it, with its messages: its Frames and Mappings are read in turn until the first that is missing, so a large `Nframe` or `Nnode` costs nothing, each must be a Frame or a Mapping, every index must be in range, the links between nodes must form a tree, and the Mappings must agree with each other and with the Frames about the number of coordinates at each node. A Plot read from a dump must have a base Frame of at most three axes, no negative number of tick mark values, and a clipping Frame that is one of its Frames with a pair of bounds for each of its axes.
- `starlink-ast`: a Frame read from a dump is checked as the C library checks it, with its messages: a SkyFrame must have two axes, and a SpecFrame, DSBSpecFrame, TimeFrame or FluxFrame one; each `Ax<n>` must be an Axis and the `Vrnts` item a FrameSet; a CmpFrame's components must be Frames, a missing one being a Frame of one axis, and its `Axp` values a permutation; a SpecFluxFrame's components must be a SpecFrame and a FluxFrame. A SkyFrame whose dump does not describe an axis gives it a SkyAxis, so its values are formatted as sky values, as in C; it had a plain Axis.
- `starlink-ast`: a Frame read from a dump with a `Prm` value of zero or less fails with `ErrorCode::Prmin`, as in the C library; the value was ignored. A missing `Nout` in a Mapping's dump is its `Nin` and an explicit zero or negative one is 0, as in C; either was taken as `Nin`. An Object whose associated KeyMap is of another class fails to load, as in C.
- `starlink-ast`: reading an object reads each value as the C library does and fails with its error and messages: a number that is not a whole decimal integer, or that a C `int` cannot hold, read where an integer belongs (`Nin = 2147483648`, `1.5`), a value that is not a finite number where a floating point number belongs (`1e999`, `nan`, `abc`), an Object where text or a number belongs, or text where an Object belongs, is `ErrorCode::Badin` with `astRead(Channel): The value "nin = 2147483648" cannot be read as an integer.` or C's text for the case; such a value was taken as a large integer, truncated, or replaced by a default. Text that looks like a number (`Title = 3`) is read as text, and a hexadecimal number (`0x10`) as a number, as in C.
- `starlink-ast`: an object that fails to load reports the C library's messages after the first: `Failed to read the "<item>" Object value.` for the innermost Object read as an item's value, and `Error while reading a <class> from a Channel.` for the object being read, which were missing when the load itself, rather than the reading of the text, failed.
- `starlink-ast`: a Frame may have no axes, as in the C library, so a conversion that shares out a Frame's axes between the components of a nested CmpFrame, and can give one of them none, finds no conversion, or the one the C library finds, rather than failing with `ErrorCode::Naxin`. `BasicFrameBuilder::build` no longer refuses zero axes.
- `starlink-ast`: two SpecFluxFrames whose SpecFrames do not convert, because their Domains differ for example, do not convert either, as in the C library; a conversion was found.
- `starlink-ast`: `Frame::cast` gives what the C library's `astCast` gives: a copy of a Frame or Region into its own class, of a SpecFluxFrame into a CmpFrame, of a Plot into a FrameSet, and of a Region or FrameSet's current Frame into a class that is neither a Region nor a FrameSet. It gave nothing in each of these cases. A CmpFrame is not cast into a SpecFluxFrame, as in the C library now.
- `starlink-ast`: an `IntraMap` whose transformation fails reports the C library's message, `astTransform(IntraMap): Error signalled by "<name>" transformation function.`, after the transformation's own message if it gave one; the two were joined on one line, with a trailing colon when the transformation gave none.
- `starlink-ast`: a blank sky axis value split into fields is one field of zero, as in the C library now; it gave no fields and a bad value.
- `starlink-ast`: a TimeFrame's `centre` with a date Format, at a gap that changes the day or a time field, is the start of the coarser unit, such as midnight or the first of the month, so that ticks a whole number of hours or days apart fall on round values; at a gap that changes the month or year it is the start of the month or year inside the window, such as 1 April for 31 March at a gap of a day. It reported `Inter` for a window across a month or year end, and gave the last day of the previous month at a gap of a day. The C library gives the day before the first of the month, and a multiple of the gap for a month or year; `docs/issues/c-library-quirks.md` sets out why the port differs.
- `starlink-ast`: a TimeFrame value, Label or Title that has no calendar date is formatted as `<bad>`, as the C library now does; it was formatted from a date of zeros. The seconds of a date have at most 9 decimal places, as in the C library; more gave digits of no meaning. A date with a year or month that is not valid is refused with the C library's message naming it, rather than "Date/time does not have the correct form."
- `starlink-ast`: a Format the C library cannot use for an axis value (a second conversion, `%s`, `%n`, a `*` width, a length modifier) is refused with the C library's `ErrorCode::Fmter` message naming the Format, when a value is formatted or split into fields; `fields` with such a format split the text. `%a`, `%A` and the `'` flag, which the C library accepts, now format a value (`%a` as C11 specifies, rounding a tie to even, and otherwise as the macOS C library writes it); they were refused. A value too long for the C library's buffer is reported with both of its messages.
- `starlink-ast`: a `%c` Format formats a value of 128 to 255 as the character of that code in ISO 8859-1, where the C library writes the byte; it failed with an internal `ErrorCode::Fmter` error.
- `starlink-ast`: simplifying a PermMap whose permutation names a constant it does not have, as one read from a dump or made by `pick_axes` can, gives a bad value there, as in the C library; it panicked when the PermMap was merged with its neighbors.
- `starlink-ast`: the PermMap `pick_axes` gives for an axis the Frame does not have, or for no axes, has a Native dump like the C library's, writing `-1` for an axis with no partner and `OutCpy = 1` or `InCpy = 1` for an empty permutation; it wrote `0`, and no `OutCpy` or `InCpy`.
- `starlink-ast`: a `Polygon` with an undefined vertex, as one read from a dump can have, reports the C library's `ErrorCode::Badin` naming the vertex when it is used; it reported an internal error.
- `starlink-ast`: a `Polygon` whose vertices all coincide, or are so far apart that their distances overflow, is made and used as in the C library; the first reported an internal error and the second hung. A Polygon with a bad or NaN vertex is refused when it is made, with the C library's `ErrorCode::Badin`; it reported an internal error when used. `Frame::line_def` gives no line only for a `BAD_VALUE` coordinate, as the C library's does; it also gave none for a NaN or infinite one.
- `starlink-ast`: an `Ellipse` moved to the centre it already has, as when it is the uncertainty of a Region with the same centre, is left as it is, as in the C library now; it failed with `ErrorCode::Badin`, "The supplied points do not determine an ellipse".
- `starlink-ast`: a `CmpRegion` that ANDs two unbounded Regions is not bounded, as in the C library now; one that ANDed two nested unbounded Regions was reported bounded. A `Prism` overlapping a negated Region uses the axes picked from it un-negated, as the C library now does, so the negation is allowed for once; the overlap of a Prism with the negation of a Box holding it, or with its own negation, was wrong. The messages for a `CmpRegion` or `Prism` with no mesh spell "because".
- `starlink-ast`: `Region::overlap` finds the overlap of a Region that has no boundary mesh and more current than base Frame axes, as the C library does; it reported an internal error. A Region with no mesh whose negation has none either, such as a Prism unbounded on one side, is reported with the C library's internal error; it overflowed the stack. Two Intervals of more than one axis that are each other's negation on one axis are each other's negation, or do not overlap, as in the C library; that panicked. The errors for two Regions with no mesh are the C library's messages, naming the classes.
- `starlink-ast`: `regions::mask` with a Region that has no upper or lower limit masks the pixels on the right side of it, as the C library does; it panicked in a debug build and treated every pixel as outside the Region in a release build. Its errors for a grid or Mapping of the wrong dimensions, or bounds in the wrong order, are now the C library's two messages, naming the element type and the Region's class.
- `starlink-ast`: the grid of points inside a Region (`Region::region_grid`, and a Frame's grid) limits its points as the C library does. An axis of no width gets two ticks and no longer counts toward the spacing of the others; a grid of more points than the C library can hold, in a Frame or a CmpFrame, is refused with `ErrorCode::Attin`; a sky box of no width uses a bounded number of parallels and, like a very narrow one, reports that it has no points. Such a Box panicked, or took tens of seconds.
- `starlink-ast`: a `FitsChan` refuses to read a grism axis whose equation has no solution at the reference wavelength, or whose order is zero, as the C library does, and reports a spectral algorithm it cannot implement with both of the C library's messages. It read such a header.
- `starlink-ast`: a card that `FitsChan::find_fits`, `write_fits` or `show_fits` cannot format is reported with the C library's `astFindFits(FitsChan): ` prefix, and `write_fits` and `show_fits` write the cards before it, as the C library does. They wrote none.
- `starlink-ast`: a `FitsChan` read of a FITS-WCS, FITS-PC, FITS-IRAF, FITS-AIPS or FITS-AIPS++ header refuses an axis keyword whose axis or parameter number the C library cannot store (`CDELT100`, `PC1_101`, `CRVAL0` and the like), with the C library's internal error, at the first such card. It ignored the card, and read the header.
- `starlink-ast`: a `FitsChan` write treats a SkyFrame as celestial only when its Domain is SKY, as the C library does, so a SkyFrame in another Domain (POLANAL, say) beside a celestial one is written as two ordinary axes. It wrote nothing for such a FrameSet, and gave a degenerate axis of such a SkyFrame the scale of its partner axis.
- `starlink-ast`: a card a `FitsChan` writes has its comment without leading or trailing white space, as in the C library, Unicode white space included; the comment of an offset sky axis with an empty Symbol began with a blank.
- `starlink-ast`: `FitsChan::get_fits_i`, `get_fits_k` and `get_fits_ci` refuse a floating-point value the integer type cannot hold with `ErrorCode::Ftcnv`, as the C library now does, where they returned the nearest value the type holds; a grism diffraction order an `i32` cannot hold is refused when a header is read; and a conversion error's message is the C library's, without the error code's description in front.
- `starlink-ast`: a `FitsChan` read refuses a WCSAXES that is not from 1 to 999 with `ErrorCode::Bdfts` and the C library's message, and one above 99, which FITS keywords cannot index, with C's internal error; a huge value made the read run for ever.
- `starlink-ast`: finding the numbers of inputs and outputs of a nested `CmpMap` takes a time proportional to its size; it was exponential in the depth of nesting, so reading a FITS header with a few tens of WCS axes did not finish.
- `starlink-ast`: a `FitsChan` writes DATE-OBS as the C library does, from the same calendar conversion, and none for an MJD-OBS that is not finite or has no calendar date. It wrote one for an MJD of 1e10, and differed from C for years before 1900 and the last instant of a day.
- `starlink-ast`: a `FitsChan` with a `FitsDigits` larger than a card can hold writes floating-point values as the C library now does, using no more digits than fit; a very large one, such as -100000, panicked, and others failed with `ErrorCode::Bdfts`.
- `starlink-ast`: a `FitsChan` writes the description of absolute coordinates for an offset sky system under a version letter no other description has, as the C library now does; it could reuse the letter a Frame's `Ident` had claimed, mixing the two descriptions. FITS-PC also refuses a secondary description with projection parameters the primary one lacks, or a different number of axes, as C does.
- `starlink-ast`: a `FitsChan` write no longer panics on a FrameSet with two world axes that depend on one pixel axis, and writes nothing, as the C library does, for a FrameSet whose Mapping holds a CmpMap with `Ident` set, one whose distorted celestial axes share pixel axes with others, one with two spectral axes or two different sky coordinate systems, and one whose celestial reference point cannot be found. It wrote a description of some of them that the C library does not, and failed on another with `ErrorCode::Innco`.
- `starlink-ast`: a `FitsChan` write that fails, or abandons a secondary axis description, puts back the cards it had overwritten, as the C library now does; it lost them, and the values they held.
- `starlink-ast`: `simplify` no longer merges a `MatrixMap` with the Mappings beside it in parallel, which the C library never does; a diagonal MatrixMap with a zero on its diagonal, used inverted beside a WinMap, became a WinMap whose inverse gave bad values where the original gave zero.
- `starlink-ast`: a `CmpMap` with `Ident` set is not split by `map_split`, as in the C library, which does not decompose a Mapping that may not be simplified; other CmpMaps are split component by component, each falling back to a search of its own inverse, as in C.
- `starlink-ast`: a `PermMap` with `perm_split` set gives no split from `map_split` for an input fed by a bad value or by an output it does not have, as in the C library; it split such an input off as if fed by that output.
- `starlink-ast`: two `WcsMap`s cancel in `simplify` only if each axis holds as many projection parameters in both, as in the C library; one whose parameter had been set and then cleared cancelled the inverse of one that never had it.
- `starlink-ast`: `simplify` no longer swaps a `PermMap` whose outputs are all constant with the Mappings in parallel after it, nor one whose inverse copies an output to an input feeding a constant block, as the C library now refuses both. The swap gave a Mapping whose inverse transformation differed from the original's.
- `starlink-ast`: `simplify` merges a `MatrixMap` with a neighbor, or swaps it past a `WinMap`, only when the result is equivalent and its matrices have values, as the C library now does. A full MatrixMap with zeros off the diagonal used inverted was replaced by its own inverse; a Mapping holding an inverted singular MatrixMap, or a diagonal one with a zero on its diagonal, failed to simplify with `ErrorCode::Mtrml` or `ErrorCode::Mtrmt`; a WinMap moved past a MatrixMap that discards an axis lost its shift from the inverse transformation; and a WinMap with no usable scale failed with `ErrorCode::Mtrmt`.
- `starlink-ast`: `Mapping::rate` at a position so close to zero that the first step it tries underflows (below about 1e-301) returns the rate; it looped for ever.
- `starlink-ast`: two Mappings holding the same infinite or NaN value, such as a ShiftMap with an infinite shift and a copy of it, are equal, as in the C library; the comparison found such a value unequal to itself.
- `starlink-ast`: a `SplineMap` gives a bad value outside the area its spline covers, which is less than the full range of the knots when the first or last knots along an axis are not coincident, and for a NaN input; it panicked for some such positions and gave a value for others. On the upper limit of that area it gives the spline's value, where it gave a bad value for a spline with one knot interval along an axis.
- `starlink-ast`: compiled for WebAssembly in the browser (`wasm32-unknown-unknown`), where the standard library cannot read the clock, the crate reads the browser's clock through `js-sys`, a dependency on that target only, so making a MathMap and reading `TimeFrame::current_time`, which a date axis's tick spacing does, no longer stop the program.
- `starlink-ast`: writing an object that is not a FrameSet to a FitsChan in an encoding other than NATIVE writes nothing and returns 0, as the C library's `astWrite` does, rather than failing.
- `starlink-ast`: `SvgGrf` draws a control character other than tab, newline and carriage return, which XML does not allow, as U+FFFD, so such a label no longer makes the SVG invalid.
- `starlink-ast`: `SvgGrf` escapes `&`, `<`, `>` and `"` in text, so a label such as `Flux < 1` no longer makes the SVG invalid.
- `starlink-ast`: `LogGrf` and `SvgGrf` measure text by characters rather than bytes, so an accented label or title is as wide as an unaccented one; ASCII text measures as before, and as the C library measures it.
- `starlink-ast`: a Unit of a SpecFrame, DSBSpecFrame or TimeFrame, or a unit given with a value, that holds text which is not ASCII (`"é"`) no longer panics in the units parser, which compared parts of it by byte position.
- `starlink-ast`: `SpecFrame::set_unit` and `DSBSpecFrame`'s store the Unit without trailing white space, as the C library does; it was kept as given.
- `starlink-ast`: a date read from text with a year of two digits or fewer is in the C library's century, 2000 to 2049 for 0 to 49 and 1950 to 1999 for 50 to 99, as the C library's `astReadDateTime` reads it.
- `starlink-ast`: simplifying a WinMap next to a parallel CmpMap keeps each simplified half in the orientation the simplifier returned it, as the C library does, so a Native dump of the result records `Invert` and `IsSimp` on that half as C's does; transforms are unchanged.
- `starlink-ast`: simplifying a Mapping that holds an inverted WinMap forms the inverse shift as the C library does, as the shift times minus the reciprocal scale, so the simplified WinMap can differ from earlier releases, and now agrees with C, in the last bit of a shift.
- `starlink-ast`: a SkyFrame's `line_crossing` gives the crossing's longitude as the C library does when the crossing lies opposite its first estimate on the -x meridian, -pi where it gave +pi.
- `starlink-ast`: the line methods `line_contains` and `line_crossing` report `ErrorCode::Inter`, as the C library does, when given a line that a different kind of Frame made: a great-circle line made by a SkyFrame given to a plain Frame, or the reverse.
- `starlink-ast`: a date whose day is outside its month, such as `2012-03-00` or `2012-02-30`, reads as the C library reads it, counting on from the start of the month, where it was not read at all.
- `starlink-ast`: the guide's Cargo chapter gives the crates.io dependency, `starlink-ast = "0.1"`, rather than saying the crate is unpublished and must come from its repository.
- `starlink-ast`: SlaMap's conversions between equatorial and horizon coordinates (`E2H` and `H2E`) take the sine and cosine of each angle with the platform's combined function, as the C library built with clang or GCC does; an unoptimized build on macOS had differed from an optimized one, and from the C library, in the last bit of some azimuths and elevations.
